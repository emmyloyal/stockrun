# Circuit specification

The TypeScript reference model in `circuits/reference/` implements exactly this spec and is the source of truth.
Quantities are in order units (cartons, bags). Money is in units of ₦5,000. The vault fills every input.

Output encodings shared by all circuits: `decision` is 2 bits, `reason` is 3 bits.

---

## 1. RestockGuard — 34 inputs → 5 outputs
Decides whether an order may lock funds.

| Bits | Name | Meaning | Source |
| --- | --- | --- | --- |
| 8 | `total` | Order total (units of ₦5,000, 0–255): the goods, plus StockRun's fee for naira orders. **Never a delivery fee** (paid to the courier directly) | Negotiated price saved to the order |
| 8 | `budget` | Remaining weekly budget | Vault storage |
| 8 | `limit` | Owner's auto-approve limit | Vault storage (owner-set, 24 h delay) |
| 2 | `sup` | 00 unknown, 01 approved, 10 preferred, 11 blocked | Supplier registry |
| 3 | `cat` | 0–5 everyday stock, 6–7 needs owner | Order |
| 2 | `dist` | 00 <2 km, 01 2–5 km, 10 5–10 km, 11 >10 km | Order (from map) |
| 1 | `ownerOk` | Owner approved this order | Owner signature |
| 2 | spare | Must be 0 | — |

Rules (first match wins):
1. `sup` ∈ {00, 11} → REJECT (00), reason 1
2. `total > budget` → REJECT, reason 2
3. `!ownerOk && total > limit` → ASK_OWNER (01), reason 3
4. `!ownerOk && cat >= 6` → ASK_OWNER, reason 4
5. `!ownerOk && dist == 11` → ASK_OWNER, reason 5
6. otherwise → APPROVE (10), reason 0

## 2. PickupCheck — 27 inputs → 13 outputs
Decides how much the supplier is paid at pickup.

| Bits | Name | Meaning |
| --- | --- | --- |
| 1 | `atSupplier` | Handover confirmed by the handler. Self-pickup: the signed-in buyer confirms they (or someone they sent) have the goods; no location rule. Logistics: the company's signed pickup report |
| 8 | `ordered` | Units ordered |
| 8 | `aiCount` | Units counted by AI in a pickup photo (check service). With no photo the vault passes `riderCount`, so the handler's count stands |
| 8 | `riderCount` | Units confirmed by the handler (owner or logistics company) |
| 1 | `damage` | AI flags visible damage |
| 1 | `bonded` | **Trusted handler**: the owner (self-pickup) or an owner-approved logistics company (vault computes; the wire keeps its taped-out name) |

Rules (first match wins):
1. `!atSupplier` → HOLD (00), reason 1
2. `!bonded` → HOLD, reason 2
3. `damage` → HOLD, reason 3
4. `payQty = min(aiCount, riderCount, ordered)`; `payQty == 0` → HOLD, reason 4
5. `payQty < ordered` → PAY_PART (01), reason 5; else PAY_FULL (10), reason 0

Outputs: `decision` (2), `payQty` (8; 0 when HOLD), `reason` (3).

## 3. DeliveryCheck — 21 inputs → 13 outputs
Records whether the goods arrived in full or short. **It moves no money.** The buyer pays the delivery fee to the
logistics company directly, outside StockRun, and the seller was already paid at pickup. Not used for self-pickup.
The vault stores the verdict on the order (`deliveryVerdict`: 2 in full, 1 short; `shortQty`) and emits
`DeliveryRecorded(id, verdict, shortQty, reason)`. Naira orders save the same call in their circuit evidence. On
COMPENSATE (a short delivery), the record is the buyer's evidence for a claim against the company. The netlist is
unchanged (taped out); only what the vault does with the output changed.

| Bits | Name | Meaning |
| --- | --- | --- |
| 1 | `atShop` | Rider's signed GPS inside shop geofence |
| 8 | `picked` | `payQty` recorded at pickup |
| 8 | `delivered` | Units AI counts in delivery photo |
| 1 | `damage` | AI flags damage at delivery |
| 1 | `ownerOk` | Owner confirmed receipt |
| 1 | `ownerIssue` | Owner reported a problem |
| 1 | `timeout` | 24 h since arrival, owner silent |

Rules (first match wins):
1. `!atShop` → WAIT (00), reason 1
2. `damage` → HOLD (00), reason 3
3. `delivered < picked` → COMPENSATE (01), reason 4, `shortQty = picked − delivered`
4. `ownerIssue` → HOLD (00), reason 2
5. `ownerOk || timeout` → PAY_RIDER (10), reason 0. The name is from the netlist; today it means "delivered in full"
6. otherwise → WAIT (00), reason 5

Outputs: `decision` (2), `shortQty` (8; 0 unless COMPENSATE), `reason` (3).

## Shared sub-circuits
All three blocks take `a` (inputs 0–7) and then `b` (inputs 8–15), LSB-first. Reference functions are `cmp8`, `min8` and `sub8` in `reference/circuits.ts`.

| Block | Output | NAND gates | Design |
| --- | --- | --- | --- |
| `CMP8` | 1 bit: a > b | 45 | Ripple from the LSB: g = MAJ(aᵢ, ¬bᵢ, g) |
| `MIN8` | 8 bits: min(a, b) | 67 | Tie-free compare (bit 0 seeds g = a0), then an 8-bit mux |
| `SUB8` | 8 bits: (a − b) mod 256 | 75 | a + ¬b + 1, ripple carry. DeliveryCheck only uses it when a ≥ b |

- `a < b` is `CMP8(b, a)`.
- Netlists are generated by `circuits/netlists/` (a TypeScript NAND compiler) and written to `circuits/build/*.json` (`npm run build-netlists`).
- Tests check them exhaustively, all 65,536 pairs, against the reference model.
- The big circuits can inline these blocks (flat) or reuse them via REF.

## Netlists (flat, blocks inlined; no REF)
Generated by `circuits/netlists/circuits.ts` into `circuits/build/*.json`.

| Circuit | In → out | NAND gates | eval gas (≈2.3k/gate) | Verification |
| --- | --- | --- | --- | --- |
| RestockGuard | 34 → 5 | 119 | ≈ 0.28M | Boundary grid × every value of sup/cat/dist/ownerOk; 100k random |
| PickupCheck | 27 → 13 | 210 | ≈ 0.49M | 15³ boundary values × all flags; 100k random (biased towards `ordered`) |
| DeliveryCheck | 21 → 13 | 141 | ≈ 0.33M | **Entire input space (2²¹)**; 100k random |

How the circuits are built:
- RestockGuard uses two CMP8s.
- PickupCheck uses two tie-free MIN8s and one CMP8. `payQty < ordered` is computed as `min(ai, rider) < ordered`.
- DeliveryCheck uses one SUB8. `delivered < picked` is computed as "picked − delivered has no borrow and is non-zero", so the subtractor is shared.

Fault injection (`node circuits/scripts/fault-check.ts`) forces every gate stuck at 0 and at 1:
- All faults are detected, except one in DeliveryCheck.
- That fault (gate s95 stuck at 1) is provably redundant: it changes no output over all 2²¹ inputs.

## Bit order
TapeOut (TAP-02 §5): vector bit i = bit (i mod 8) of byte floor(i/8), LSB-first. Input i is signal 2+i, and outputs are the last nOut signals.
StockRun convention: fields are laid out in the order listed in this file. Within a field, wire k = bit k of the value (LSB-first).
`circuits/reference/pack.ts`, `StockRunVault._pack/_unpack` and the netlists must all follow this. See docs/TAPEOUT_NOTES.md.
